# 에이전트 포스팅 가이드

이 문서는 **뉴스/채용 큐레이션 에이전트**가 crit에 콘텐츠를 게시하는 방법을 정의합니다.
사람이 읽어도 되지만, 1차 독자는 매일 실행되는 AI 에이전트입니다.

## 원칙

- **콘텐츠 = 파일 = git 커밋.** DB 쓰기, API 호출 없이 `content/` 아래 파일을 추가하고
  커밋/푸시하면 게시가 완료됩니다. 배포(Vercel 등)는 push에 연동됩니다.
- 게시 전 반드시 `npm run validate` 를 실행해 통과해야 합니다. CI에서도 같은 검증이 돌며,
  실패한 커밋은 배포되지 않습니다.
- 하루 아티클 수는 카테고리 합산 **3~7개**를 권장합니다. 양보다 큐레이션 밀도가 중요합니다.

## 1. 아티클 게시

### 파일 위치와 이름

```
content/articles/YYYY-MM-DD-kebab-case-slug.md
```

- 날짜는 게시일(KST 기준). frontmatter의 `date`와 반드시 일치해야 합니다.
- slug는 소문자 영문/숫자/하이픈만. 내용을 짐작할 수 있게 짓습니다.

### frontmatter 스키마 (`lib/schema.ts`의 zod 스키마가 원본)

```yaml
---
title: "제목 (120자 이내)"                # 필수
summary: "한두 문장 요약 (300자 이내)"     # 필수. 피드 카드에 노출됨
category: news                            # 필수. 아래 카테고리 중 하나
tags: [figma, ai]                         # 선택. 최대 8개
date: "2026-07-28"                        # 필수. YYYY-MM-DD
source_url: "https://..."                 # 선택. 외부 원문이 있으면 필수 권장
source_name: "Figma Blog"                 # 선택. 출처 표기
thumbnail: "https://..."                  # 선택
author: "crit agent"                      # 선택. 기본값 "crit agent"
---
```

### 카테고리

| 값 | 표시명 | 다루는 것 |
|---|---|---|
| `news` | 뉴스 | 디자인 업계/도구 뉴스, 릴리즈 소식 |
| `ai-workflow` | AI 워크플로우 | AI를 실무 프로세스에 결합하는 방법 |
| `tools` | 도구 | 도구 추천, 비교, 활용법 |
| `ai-guide` | AI 사용법 | 프롬프트 작성법, AI 기초 활용 가이드 |
| `portfolio` | 포트폴리오 | 포트폴리오 리뷰, 케이스 스터디 분석 |

### 본문 작성 규칙

- 마크다운(GFM). 표, 인용, 코드 블록 사용 가능. `h2(##)`부터 시작합니다.
- 모바일 독자 기준: 문단은 3줄 이내, 섹션은 4개 이내로 짧게 씁니다.
- 외부 기사 큐레이션이면 **번역·요약 + 왜 중요한지 코멘트**를 담고, 반드시
  `source_url`을 넣습니다. 원문 전체를 복사하지 않습니다.
- 한국어로 작성합니다. 도구/기능 고유명사는 원문을 유지합니다.

## 2. 채용 공고 게시

### 파일 위치와 이름

```
content/jobs/YYYY-MM-DD.json
```

하루치 공고를 파일 하나에 담습니다. 같은 날 재실행하면 기존 파일을 덮어씁니다.

### 스키마

```json
{
  "date": "2026-07-28",
  "jobs": [
    {
      "id": "2026-07-28-company-role",     // 필수, 전체 파일에서 유일해야 함
      "company": "회사명",                  // 필수
      "title": "포지션명",                  // 필수
      "location": "서울 강남 / 원격 가능",   // 필수
      "employment_type": "full-time",       // full-time | contract | freelance | internship
      "experience": "경력 3년+",            // 선택
      "salary": "6천~8천",                  // 선택
      "tags": ["프로덕트디자인"],           // 선택, 최대 8개
      "url": "https://...",                 // 필수, 지원/공고 링크
      "posted_at": "2026-07-28",            // 필수
      "expires_at": "2026-08-28"            // 선택, 지나면 목록에서 자동 제외
    }
  ]
}
```

- `id`는 `YYYY-MM-DD-회사-포지션` 패턴을 권장합니다. **이전 날짜 파일과도 중복 금지**
  (validate가 전체 파일을 교차 검사합니다). 같은 공고를 다시 싣지 않습니다.

## 3. 게시 절차 (에이전트 체크리스트)

```bash
# 1. 최신 상태로
git pull origin main

# 2. 콘텐츠 파일 작성 (위 스키마대로)
#    헬퍼: npm run new:article -- news my-slug "제목"

# 3. 검증 — 실패하면 고치고 다시
npm run validate

# 4. 커밋 & 푸시
git add content/
git commit -m "content: 2026-07-28 데일리 큐레이션 (아티클 4건, 채용 3건)"
git push origin main
```

- 커밋 메시지는 `content: <날짜> 데일리 큐레이션 (아티클 N건, 채용 N건)` 형식.
- 코드(`app/`, `lib/` 등)는 절대 수정하지 않습니다. 콘텐츠 커밋은 `content/`만 건드립니다.
- 검증 실패를 스스로 해결할 수 없으면 게시를 중단하고 이슈를 남깁니다.

## 4. 소스 선정 기준

- 디자이너에게 실질적으로 유용한가? (읽고 나서 행동이 바뀌는가)
- 국내 독자 기준으로 맥락 보충이 필요한가? (필요하면 코멘트 추가)
- 광고성/어뷰징 콘텐츠 제외. 채용 공고는 공식 채용 페이지 링크만 사용.

### 권장 수집 소스

- **뉴스/도구**: Figma·Adobe 등 공식 블로그, AI타임스, 요즘IT, 디지털인사이트,
  Smashing Magazine, Nielsen Norman Group
- **AI 워크플로우/가이드**: 각 도구 공식 문서, 실무자 케이스 스터디 (개인 블로그 포함,
  단 근거가 있는 글만)
- **채용**: 토스·카카오·네이버 등 공식 채용 페이지, 원티드, 디자이너잡, 디자인루키
  — 최종 링크는 반드시 **공식 채용 페이지** 또는 원 공고 URL

### 정확성 규칙 (중요)

- **검색 스니펫만으로 세부 사실을 단정하지 않는다.** 수치·날짜·기능명은 원문에서
  확인된 것만 쓰고, 확인 불가하면 뭉뚱그리지 말고 빼라.
- 오래된 뉴스를 "오늘/이번 주" 소식처럼 쓰지 않는다. 시점이 불확실하면
  시점 표현 없이 "왜 중요한가" 중심으로 쓴다.
- 채용 공고는 마감되었을 수 있다 — 지원 링크가 살아있는지 확실치 않으면
  회사 공식 채용 페이지를 링크한다.
- 같은 소식을 다룬 아티클이 이미 있으면 다시 쓰지 않는다 (`content/articles/`
  전체에서 제목·태그로 확인).
