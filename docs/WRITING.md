# 아티클 작성 가이드

crit 아티클의 품질 기준. 에이전트와 사람 에디터 모두 이 가이드를 따른다.
파일 포맷/스키마는 [AGENT.md](./AGENT.md), 이 문서는 **내용을 어떻게 쓰는가**를 다룬다.

## 원칙

1. **읽고 나서 행동이 바뀌어야 한다.** "그래서 나는 뭘 하면 되는데?"에 답이 있어야 한다.
2. **요약이 아니라 큐레이션.** 원문 압축에 그치지 말고, 왜 중요한지 우리의 관점을 한 단락 이상 담는다.
3. **모바일 독자 기준.** 문단 3줄 이내, 섹션 4개 이내, 전체 300~700자(본문 기준) 안팎.
4. **확인된 것만 쓴다.** 수치·날짜·기능명은 원문에서 확인된 것만. 불확실하면 뺀다.

## 구조 템플릿

```
## (무슨 일인가 / 문제가 뭔가)     ← 첫 섹션에서 팩트 전달
## (디자이너에게 왜 중요한가)      ← 우리의 해석. 이 글의 존재 이유
## (지금 해볼 것 / 함께 볼 것)     ← 행동 유도로 마무리
```

- 제목: 궁금증을 만들되 낚시 금지. "X 공개 — Y가 바뀐다" 패턴 권장, 120자 이내
- summary: 피드 카드에 노출된다. 본문 첫 문장 복사 금지, 독립적으로 읽혀야 함
- 본문은 `##`(h2)부터 시작. h1은 페이지 타이틀이 이미 차지한다

## 리치 콘텐츠

### 이미지

```markdown
![Config 2026 키노트에서 공개된 Figma Motion 타임라인](https://example.com/image.png)
```

- alt 텍스트는 반드시 내용을 설명 (스크린리더 + SEO)
- **출처가 명확한 이미지만**: 공식 블로그/프레스킷 이미지, 오픈 라이선스, 직접 캡처
- 원문 전체를 이미지로 옮겨 붙이지 않는다 (저작권 + 모바일 로딩)
- 이미지 아래 줄에 `*출처: Figma 공식 블로그*` 처럼 기울임으로 출처 표기

### 유튜브 영상

**URL을 한 줄에 단독으로** 쓰면 플레이어로 임베드된다:

```markdown
발표 영상 전체는 아래에서 볼 수 있습니다.

https://www.youtube.com/watch?v=VIDEO_ID
```

- `youtube.com/watch`, `youtu.be/`, `shorts/`, `live/` 모두 지원
- 문장 안에 넣은 링크는 일반 링크로 렌더된다 (임베드는 단독 줄만)
- 영상이 글의 핵심 소스면 frontmatter `source_url`에도 영상 URL을 넣는다

### X(트위터) 포스트

마찬가지로 **포스트 URL을 한 줄에 단독으로**:

```markdown
디자이너들의 첫 반응은 이렇습니다.

https://x.com/username/status/1234567890
```

- `x.com`, `twitter.com` 상태(status) URL 지원
- 삭제될 수 있는 포스트이므로, 포스트의 핵심 내용을 본문에도 한 줄로 요약해둔다

### 일반 링크 카드 (썸네일 미리보기)

유튜브/X가 아닌 URL도 **한 줄에 단독으로** 쓰면 썸네일·제목·설명이 있는
링크 카드로 렌더된다 (OG 메타데이터 자동 추출):

```markdown
원문에서 전체 사례를 볼 수 있습니다.

https://www.figma.com/blog/some-post
```

- 문장 속 링크는 일반 텍스트 링크로 유지된다 — 카드는 강조하고 싶은 1~2개만
- `source_url`과 같은 링크를 본문 카드로 또 넣지 않는다 (상단 "원문 보기"와 중복)

### 표 / 인용

- 비교는 표로 (`tools` 카테고리에서 특히). 열 4개 이하 — 모바일에서 깨진다
- 원문 직접 인용은 `>` 인용구로, 번역 시 원문 뉘앙스 유지

## 카테고리별 포인트

| 카테고리 | 핵심 질문 | 권장 리치 콘텐츠 |
|---|---|---|
| news | 무슨 일이고 나에게 어떤 영향? | 공식 이미지, 발표 영상 |
| ai-workflow | 내 프로세스에 어떻게 끼워 넣나? | 단계 스크린샷, 데모 영상 |
| tools | 뭐가 다르고 언제 갈아타나? | 비교 표, 데모 영상 |
| ai-guide | 따라 하면 되는 수준으로 구체적인가? | 프롬프트 코드블록, 예시 이미지 |
| portfolio | 뭘 배워서 내 것에 적용하나? | 케이스 이미지 (권한 확인 필수) |

## 문체

- 한국어 존댓말 평서형 ("~합니다"). 개조식("~함") 금지
- 도구/기능 고유명사는 원문 유지 (Figma Motion, Code Layers)
- 과장 금지: "혁명적", "게임체인저" 대신 무엇이 구체적으로 달라지는지
- 이모지는 쓰지 않는다
