# 아티클 스타일 레지스트리

`format`과 `style`은 서로 다른 축으로 관리함.

- `format`: 아티클을 사이트에서 어떻게 보여줄지 결정함. (`brief`, `deep`, `rules`, `showcase`)
- `style`: 원문의 성격에 맞춰 어떤 편집 문체로 전달할지 결정함.

새 원문을 쓰기 전에 **style을 먼저 고르고**, 그 다음 글의 길이와 렌더링에 맞는 `format`을 고름.

## 스타일 선택표

| style | 적합한 원문 | 핵심 운영 원칙 | 보통 format |
|---|---|---|---|
| `geeknews` | 뉴스, 발표, 기술·디자인 아티클 | 30초 안에 핵심 파악. 상단 3~5개 요약 불릿. 사실과 의견 분리 | `brief` 또는 `deep` |
| `source-faithful` | 에세이, 편지, 선언문 | 화자의 I/you, 순서, 질문, 망설임을 보존. 제3자 해설로 바꾸지 않음 | `deep` |
| `interview` | 인터뷰, 대담, 팟캐스트 | 발화자와 질문-답변 순서 보존. 개인 주장을 사실로 일반화하지 않음 | `deep` |
| `reference` | 규칙, 체크리스트, 사용법 | 항목의 조건·예외·예시 보존. 번호와 실제 수록 항목 수를 일치시킴 | `rules` |
| `showcase` | 브랜드, 제품, 캠페인, 작업 사례 | 과정·적용물·비주얼을 문단 가까이 배치. 대표 이미지 재사용 금지 | `showcase` |

## 긱뉴스(`geeknews`) 스타일

### 목적

원문을 대체하는 번역문이 아니라, **클릭 전에 읽을 가치와 핵심 주장을 판단할 수 있는 큐레이션**을 만듦.

### 구조

```md
# 핵심 사실이 드러나는 명사형 제목

• 누가 무엇을 다루는지
• 원문의 핵심 주장
• 결정적인 근거·숫자·사례
• 남아 있는 긴장 또는 조건

> 출처: https://example.com/article

## 원문의 논지 단위로 만든 섹션

• 한 불릿에 한 문장
• 핵심 키워드 1~2개는 **볼드**

## crit의 관점

원문 요약과 분리된 짧은 관점. 동의나 반론, 구체적인 제한, 남는 문제를 추상적인 조언 없이 씀.
```

### 작성 규칙

- 제목은 원문을 직역하지 않고 핵심 사실이 드러나는 명사형으로 재구성함
- 상단 요약은 3~5개 불릿으로 작성하고 첫 불릿에 출처와 주제를 포함함
- 원문 용어는 첫 등장에 `한국어(English)`로 병기함
- 숫자, 버전, 고유명사, 사례와 원문의 순서·긴장을 유지함
- 본문에는 원문에 없는 비유, 해석, 개인 감상을 넣지 않음
- 저자의 주장은 저자의 것으로 귀속하고, 반박은 `crit의 관점`에서만 다룸
- `-함`, `-임`, `-됨`, `-다`를 문맥에 맞게 섞되 문장마다 기계적으로 반복하지 않음
- 경어체, 클릭베이트, 과장 부사, 의미 없는 마무리를 쓰지 않음
- 에디터 노트는 본문보다 짧게 유지하고 마지막에 구체적인 질문 하나를 둠

## 운영 예시

```yaml
format: brief
style: geeknews
```

같은 긱뉴스 문체라도 원문이 길고 논지 단위가 많으면 `format: deep`으로 바꿀 수 있음. 반대로 규칙 모음은 `style: reference`와 `format: rules`를 함께 사용함.

## 새 스타일 추가 절차

1. `lib/editorial-styles.ts`에 식별자, 표시명, 적용 조건, 작성 규칙을 추가함.
2. 이 문서의 선택표와 상세 규칙을 추가함.
3. `lib/schema.ts`가 새 값을 허용하는지 확인함.
4. `npm run new:article -- <category> <slug> "제목" <style>`로 템플릿을 생성함.
5. `npm run validate`와 `npm run build`를 실행함.
