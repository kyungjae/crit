Config 2026에서 Figma가 보여준 방향은 명확합니다. 디자인 파일은 더 이상 정적인 화면을 정리해두는 장소에 머물지 않습니다. AI 에이전트가 시안을 만들고, Motion이 움직임을 붙이고, Code Layers가 실제 코드와 연결되면서 캔버스는 점점 제품 제작 환경에 가까워지고 있습니다.

개별 기능만 보면 각각 다른 발표처럼 보입니다. 하지만 한 줄로 묶으면 Figma의 방향은 “핸드오프 이전의 더 많은 작업을 파일 안으로 가져오겠다”에 가깝습니다.

## 에이전트는 반복 작업을 캔버스 안으로 가져옵니다

Figma 에이전트는 디자인 파일 안에서 반복 작업을 도울 수 있는 방향으로 소개되었습니다. 시안 변형, 콘텐츠 채우기, 운영성 디자인 업무처럼 시간이 들지만 판단의 난도가 상대적으로 낮은 작업이 먼저 영향을 받을 가능성이 큽니다.

여기서 중요한 질문은 “에이전트가 얼마나 똑똑한가”가 아닙니다. 에이전트가 어떤 기준을 보고 작업하는가입니다. 디자인 시스템, 컴포넌트 규칙, 브랜드 톤, 접근성 기준이 파일 안팎에 정리되어 있지 않으면 에이전트는 평균적인 결과를 빠르게 만들 뿐입니다.

Figma가 에이전트를 캔버스 안에 넣는 것은 편리합니다. 동시에 위험합니다. 그럴듯한 화면이 더 많이 만들어질수록, 디자이너는 더 많이 고르는 사람이 됩니다. 생산성의 병목이 손속도에서 판단 기준으로 이동합니다.

## Motion은 디자인 시스템의 범위를 넓힙니다

Motion이 흥미로운 이유는 애니메이션 도구가 하나 더 생겼기 때문만은 아닙니다. 움직임이 디자인 파일 안에서 정의되면, 모션은 더 이상 “나중에 붙이는 효과”가 아니라 컴포넌트와 상태의 일부가 됩니다.

버튼의 hover, 카드의 등장, 로딩 상태, 전환 속도, easing은 모두 제품의 인상을 만듭니다. 지금까지 많은 디자인 시스템은 색, 타이포그래피, 컴포넌트 상태에는 엄격했지만 움직임은 별도 문서나 개발 구현에 맡겼습니다. Figma Motion은 이 간극을 줄일 수 있습니다.

하지만 모션이 쉬워질수록 과잉 사용도 쉬워집니다. 움직임은 화면을 세련되게 만드는 장식이 아니라 상태와 인과관계를 설명하는 언어입니다. “넣을 수 있다”와 “넣어야 한다”는 다릅니다.

## Code Layers는 핸드오프의 경계를 흐립니다

Code Layers는 디자인 레이어와 실제 코드 사이의 거리를 줄이려는 시도입니다. 캔버스 위에서 코드가 실행되고, 디자인 결과물과 구현 가능한 구조가 더 가까워집니다.

이 방향은 Paper 같은 차세대 디자인 도구가 던지는 질문과도 닿아 있습니다. 디자이너가 이미지에 가까운 목업을 만들고 엔지니어가 다시 코드로 번역하는 방식은 오래된 병목입니다. Figma는 그 병목을 완전히 없애기보다, 기존 협업 캔버스 안에서 조금씩 얇게 만들려 합니다.

좋게 보면 이것은 디자이너가 최종 결과물에 더 가까워지는 변화입니다. 나쁘게 보면 파일이 너무 많은 역할을 떠안게 되는 변화입니다. 디자인, 모션, 코드, 에이전트가 모두 한곳에 들어오면 캔버스는 강력해지지만 복잡해집니다.

## crit의 관점: Figma는 도구가 아니라 작업장의 위치를 바꾸고 있습니다

Config 2026의 좋은 점은 디자인과 구현 사이의 오래된 간극을 정면으로 다룬다는 데 있습니다. 에이전트, Motion, Code Layers는 서로 다른 기능이지만 모두 같은 방향을 봅니다. 디자인 파일을 결과물 보관소가 아니라 제품을 만드는 작업장으로 바꾸는 것입니다.

다만 이 방향이 항상 디자이너에게 유리하다고 말하기는 어렵습니다. 캔버스가 더 많은 일을 처리할수록, 디자이너에게 요구되는 판단도 넓어집니다. 모션을 이해해야 하고, 코드의 제약을 읽어야 하고, 에이전트의 결과를 검토해야 합니다. 툴이 쉬워지는 만큼 역할이 쉬워지는 것은 아닙니다.

Figma가 강해질수록 디자인 파일 안의 질서가 더 중요해집니다. 레이어 이름, 컴포넌트 구조, 토큰, 상태, 오토레이아웃, 문서화가 흐트러진 파일에서는 AI도, Motion도, Code Layers도 힘을 잃습니다. 툴의 진화는 파일 위생을 더 중요하게 만듭니다.

생각할 질문은 이것입니다.

- Figma 파일은 사람뿐 아니라 에이전트가 이해할 수 있게 정리되어 있는가
- 모션은 장식인가, 상태와 인과관계를 설명하는 언어인가
- 코드와 가까워지는 것이 디자이너의 판단을 넓히는가, 아니면 부담을 늘리는가
- 핸드오프가 얇아질 때 사라지는 일과 새로 생기는 일은 무엇인가
- 캔버스가 모든 것을 담기 시작하면, 무엇은 캔버스 밖에 남겨야 하는가

Config 2026은 “Figma에 기능이 많이 추가됐다”는 소식보다 큽니다. Figma는 디자인 파일의 의미를 다시 정의하려 합니다. 이 변화가 좋은 결과로 이어지려면, 디자이너는 더 많은 기능을 익히는 것만이 아니라 더 명확한 판단 기준을 파일 안에 남겨야 합니다.
